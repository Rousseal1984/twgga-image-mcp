# twgga-image-mcp v0.4.0

把 TWGGA 的生图能力包装成 MCP server，让 Claude Code、Codex、Cursor 等 MCP 客户端
直接出图、改图，结果落盘到本地，返回的是文件路径而不是几 MB 的 base64。

## 安装

从下方 Assets 下载对应平台的二进制，无需安装 Python 或任何运行时：

| 平台 | 文件 |
|---|---|
| Linux x86_64 | `twgga-image-mcp-linux-x86_64` |
| macOS Intel | `twgga-image-mcp-macos-x86_64` |
| macOS Apple Silicon | `twgga-image-mcp-macos-arm64` |
| Windows x86_64 | `twgga-image-mcp-windows-x86_64.exe` |

`SHA256SUMS` 用于校验完整性。macOS / Linux 下载后需要 `chmod +x`。

然后运行 `install` 子命令，它会把配置写进 Claude 与 Codex：

```bash
./twgga-image-mcp-macos-arm64 install
```

需要一把能访问 `gpt-image-2` 的 TWGGA API Key，在 https://twgga.work 的控制台创建。

## 提供的工具

| Tool | 用途 |
|---|---|
| `image_generate` | 文生图，一次可出多张 |
| `image_edit` | 单张参考图编辑，支持 alpha mask |
| `image_multi_reference` | 2–10 张参考图融合成一张新图 |
| `image_batch_edit` | 多张图各自套用同一条指令 |
| `server_info` | 让模型先问清楚这个服务能做什么 |

## 关于尺寸，请先读这一段

生图由订阅态线路承载，**上游把 `size` 当作建议而非要求**：请求 `1024x1024` 实测会
返回 `1122x1402`。任何尺寸都可能被重映射。

因此每个返回结果都带 `size_honored` 与 `saved.actual_size`，它们是准的——请以它们
为准，而不是以你请求的尺寸为准。需要精确构图时，把画幅要求写进 prompt 往往比传
`size` 更有效。

2K 及以上的请求会强制 `n=1` 并串行排队：一张大图会占住一个上游账号相当长时间。

## 安全边界

这个 server 会在你的机器上写文件，因此有几件事是刻意做严的：

- 上游响应里的 URL 在被下载之前先做校验，拒绝指向内网与伪造地址的目标
- 解码后的图像有像素与边长硬上限，一个很小的文件无法膨胀成一张巨图
- 所有输出路径都在配置的根目录内解析，构造过的 `basename` 逃不出去
- API Key 只从启动时的环境变量读取，运行期的工具参数不接受 base_url，避免 Key 被
  引导到攻击者的主机

## 本版变化

首个 TWGGA 版本。相对上游最要紧的差别是**只有一条生图线路**：上游那条按量计费、
能保证精确像素的线路本站尚未开通，因此不再按尺寸自动切换模型——留着它只会把请求
送到一个不存在的模型名上，让客户拿到「模型未配置价格」。

另外修掉了一批 Windows 下的问题：子进程输出按系统编码解码导致的失败、Python 与
Rust 解析家目录不一致、以及给人看的路径里混进 `\\?\` 扩展前缀。
