# twgga-image-mcp v0.5.1

修一件事：Windows 上客户端开着的时候也能升级了。

## Windows 升级不再报「拒绝访问」

- v0.5.0 在 Windows 上升级时，如果 Claude Code、Codex 等客户端正开着旧版 MCP，会报「原子替换稳定 binary 失败: 拒绝访问。 (os error 5)」，升级失败。让 AI 帮你升级时几乎一定会遇到，因为 AI 所在的客户端就开着旧版。
- 现在安装器会把正在运行的旧程序改名挪开，新程序放到原位，并提示「重启客户端（或重连 MCP）后生效」。旧进程不受影响，重启客户端后用的就是新版。
- 挪开的旧程序在下一次安装时自动清掉。万一挪开后仍放不进去，旧程序会被挪回原位，客户端照旧可用，报错里会提示先退出客户端再试。
- 失败时一切照旧：Key 已迁进系统凭据库，客户端配置不会被改动，旧版继续能用。

## 升级方式

和以前一样，重新运行一行安装命令，已保存的 Key 不用重新输入：

```powershell
irm https://raw.githubusercontent.com/Rousseal1984/twgga-image-mcp/main/scripts/install.ps1 | iex
```

```bash
curl -fsSL https://raw.githubusercontent.com/Rousseal1984/twgga-image-mcp/main/scripts/install.sh | sh
```

完成后重启客户端，调用 `server_info` 确认 `version` 为 `0.5.1`。

## 验证

- 新增 `tests/installer_running_binary.rs`：让一个程序在安装位置上真实运行，确认直接覆盖会被拒绝，再确认安装器能挪开它、放入新程序、下次安装清掉旧程序。去掉挪开逻辑时这条测试复现的正是 v0.5.0 的原报错。
- 2026-11-09 在隔离目录里模拟 v0.4.3 客户（旧程序在安装位置、Key 明文写在 Claude 配置里），在旧版 MCP 运行中执行安装：升级成功，Key 原样迁进系统凭据库，配置里的明文 Key 被移除，按改写后的配置启动 `doctor` 通过。
