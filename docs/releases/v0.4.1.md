# twgga-image-mcp v0.4.1

修一处**只存在于已发布二进制里**的文案问题。源码在 v0.4.0 发版之后就已改正，
但四个平台的产物是改正之前构建的，因此挂在 Releases 上的包仍在输出旧文案。

## 修了什么

请求尺寸与实际出图不一致时，工具会在 `notes` 里附一句说明。v0.4.0 的产物里
这句话是：

> ⚠ 实际 1672×941 ≠ 请求 1024×1024。**本站生图由订阅态线路承载，上游把 size
> 只当建议、并不保证精确像素**，请以 saved.actual_size 为准……

这段文字会原样进入客户 AI 的上下文，客户往往照着复述。它描述的是服务背后的
实现方式，而不是这个服务本身的行为，不该出现在面向客户的输出里。现在是：

> ⚠ 实际 1672×941 ≠ 请求 1024×1024。**本站生图不保证精确像素，size 只是建议**，
> 请以 saved.actual_size 为准；需要精确构图时把画幅要求写进 prompt。

`size` 提示语（`size=… 会照常请求，但本站线路不保证精确像素`）同批改正。

## 行为有没有变

没有。只是文案。工具名、参数、返回结构、落盘路径、计费口径全部与 v0.4.0 相同，
不需要改任何客户端配置。

## 该不该升

建议升。v0.4.0 能正常出图，升级只是为了拿到正确的文案。
