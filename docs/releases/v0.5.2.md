# twgga-image-mcp v0.5.2

修一件事：生图撞上服务端网关抖动时，客户不再看到一整页 HTML，而且大概率根本不会失败。

## 1K 图遇到网关快速失败时会自动补一次

2026-11-24 客户实况：一次 1K 生图，服务端 1 秒就回了 `504 Gateway Timeout`，正文是一整页 Cloudflare 的错误页。旧版本对 1K 请求的失败**一次都不重试**（重试开关是 `is_quality_model || big_size`，而本站没有"质量线路"，1K 恒为 false），于是那段 HTML 原样打到了客户眼前。

现在的规则：

- 只对**网关类**状态码补一次：502、503、504、520、521、522、523、524、525、527。
- 只在**这次尝试 30 秒内就失败**时才补：实测成功生图要 17–130 秒，30 秒内就失败说明上游还没来得及出图，补一次不会重复付钱。慢速失败可能是"图已经出来了、只是没送回来"，那种情况不补，避免为两张图付费。
- 只补一次，等待 4 秒 + 抖动，和既有小请求的重试节奏一致。
- `enabled` 的语义与取值完全不动：1K 的 400/429 这类失败仍然不重试。

服务端同日也做了对应修复（快速网关失败会被服务端自己换号重打、HTML 正文换成一句中文说法），所以现在两道兜底：服务端内部重试，客户端再补一次。

## 升级方式

和以前一样，重新运行一行安装命令，已保存的 Key 不用重新输入：

```powershell
irm https://raw.githubusercontent.com/Rousseal1984/twgga-image-mcp/main/scripts/install.ps1 | iex
```

```bash
curl -fsSL https://raw.githubusercontent.com/Rousseal1984/twgga-image-mcp/main/scripts/install.sh | sh
```

完成后重启客户端，调用 `server_info` 确认 `version` 为 `0.5.2`。

## 验证

- 新增 `gateway_retry_covers_fast_gateway_failures_only`：10 个网关状态码都给出 4 秒 + 抖动；31 秒的 504、400、已补过一次（`attempt_index=1`）都返回不重试；抖动有 2 秒上限。
- 路由表测试补断言：1K 的 `enabled` 仍为 false，`gateway_retry` 为 true。
- 本机端到端实测（假服务第一次回 504 HTML、第二次回 200 图）：工具调用返回 `ok: true`，`notes` 里能看到「HTTP 504 可重试，等待 4.1s 后第 2 次尝试」，第二次拿到图并落盘，全程 4.2 秒。
- 门禁：`cargo fmt --all -- --check`、`cargo clippy --all-targets --all-features -- -D warnings`、`cargo test` 全部通过。

## 遗留

- 补一次仍失败时，返回给客户的原因正文里可能还是网关原始响应；服务端同日更新后已经换成一句中文说法，所以正常路径不会再出现 HTML。
- 512（小图）与 1K 走同一条补试规则；≥2K 的既有重试策略未改动。
- 网关回了 `Retry-After` 时目前不看它，固定等 4 秒 + 抖动（只补一次，代价可控）。
