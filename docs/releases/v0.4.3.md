# twgga-image-mcp v0.4.3

改工具描述，让 AI 不再向你承诺做不到的分辨率。

## 为什么要改

工具描述是给 AI 看的，不是给人看的 —— 你的 Claude Code / Codex 会照着它判断
该调哪个工具、该传什么参数，也会照着它回答你「能不能出 4K」。

此前的描述里写着「用户提到高清/4K/海报/壁纸 → 传 3840x2160」，还宣称
image_edit「4K：3840×2160 成功」。这不是本站线路的实际行为。实测：

| 工具 | 请求 | 实际得到 |
|---|---|---|
| image_generate | 3840×2160 / 2048×1152 / 1536×1024 | 三次都是 1254×1254 |
| image_edit | 3840×2160 | 1672×941（约 157 万像素） |

总像素固定在约 157 万，2K 需要约 236 万、4K 需要约 829 万，都超出上限。

于是会发生这样的事：你说「画一张 4K 壁纸」，AI 照着描述答应下来、传了
3840x2160，你拿到的却是 1672×941，而且因为请求了大尺寸还额外慢了一截。

## 改了什么

- 四个工具的描述改成与实测一致，并明确写上「不要向用户承诺 2K / 4K」。
- 删掉「按关键字推断到 4K/2K 尺寸」的指引和 `size="3840x2160"` 这类示例，
  换成把画幅写进 prompt 的写法 —— 实测「16:9 宽幅横构图」得到 1672×941、
  「9:16 竖幅海报」得到 941×1672，比例很准。
- 保留仍然为真的部分：请求 ≥2K 的尺寸确实会强制单张并串行发送（只是不会更
  清晰），size 格式不合法仍会被直接拒。

工具名、参数、schema、返回结构一律未变，不需要改任何客户端配置。

## 该不该升

建议升。行为没变，但升级之后 AI 对你说的话会和实际拿到的图一致。

升级方式：下载新版二进制，再跑一次 `install`；不确定是否生效就跑 `doctor`。
